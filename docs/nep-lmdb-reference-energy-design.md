# NEP LMDB 元素参考能量训练设计

状态：设计文档；尚未修改训练代码。目标分支与目录：`nep-dcu/unep`，`/data/home/wuxingxing/xcode/MatPL-lmdb`。

## 1. 目标与范围

OMat24、MPtrj 和 MAE（MPtrj + sAlex）的 LMDB 文件继续保存原始 DFT 总能。训练普通 NEP 时，从总能标签减去对应数据类型的元素参考能量；checkpoint 保存残差网络和三套参考值；对外推理及 `nep*.txt` 输出恢复总能。

本功能仅涉及总能监督以及已有的力、维里监督。`Ei` 只作为 NEP 内部求和量；不启用或改造 `train_ei`、`E_group` 的标签、损失和日志。非 LMDB 数据路径保持现有行为。参考值不依赖坐标或晶胞，因此从能量中加减参考值不会改变力和维里。

数学约定（结构 (s)、元素 (Z)、原子数 (n_{sZ})）：

\[
R_s^{(d)}=\sum_Z n_{sZ}\mu_Z^{(d)},\qquad
E_{s,\mathrm{target}}^{\mathrm{res}}=E_{s,\mathrm{DFT}}-R_s^{(d)},\qquad
E_{s,\mathrm{physical}}^{\mathrm{pred}}=E_{s,\mathrm{net}}^{\mathrm{res}}+R_s^{(d)}.
\]

其中 (d\in\{\texttt{mptrj},\texttt{omat24},\texttt{mae}\}\)。训练、验证在残差口径计算能量损失；用户可见的推理结果和导出的文本力场使用物理总能口径。参考值是每元素常数，单位 eV/atom，结构参考和的单位为 eV。它不等同于形成能参考元素，也不直接解决不同 DFT 设置的所有结构相关误差。

## 2. 输入与参考表

在顶层增加与 `format` 并列的 `lmdb_type`：

```json
{
  "format": "lmdb",
  "lmdb_type": "omat24",
  "train_data": ["/path/to/*.aselmdb"]
}
```

| 输入值 | 内部标准值 | 参考表 |
| --- | --- | --- |
| `mptrj` | `mptrj` | 附件 `initialize_from_MPtrj`，未修正能量 |
| `omat`、`omat24` | `omat24` | 附件 `initialize_from_OMat` |
| `mae` | `mae` | 附件 `initialize_from_MPA`，MPtrj + sAlex |

大小写不敏感。`format=lmdb` 训练时要求明确填写 `lmdb_type`；非法值立即报错。一个训练任务仅选择一种参考表；`mae` 任务可以在 `train_data` 中同时列出 MPtrj 与 sAlex LMDB 文件。对非 LMDB 格式，若填写 `lmdb_type` 则报配置错误，避免参数被静默忽略。

三套系数作为一个版本化的只读表集中维护，索引约定为原子序数 `1..94`，而不是 `atom_type` 的列表位置。启动时校验每表长度、有限值、当前 `atom_type` 中每个元素是否有参考值；不在表内的元素直接报出原子序数。`nep.json` 的元素顺序仍用于模型内部类型索引，但不能改变物理元素到参考值的映射。

## 3. 数据加载和模型初始化

`NepLmdbDataset` 在解析原始 `energy` 和 `numbers` 后计算 `R_s`。样本中的 `energy` 提供残差标签；另保留原始总能供推理报告使用。训练集与验证集必须应用同一套参考值。计算按单结构原子序数直接查表并求和，不逐 epoch 拟合，也不修改 LMDB 文件。collate 保持现有 `torch.stack` 行为。

当前 `LmdbEnergyStatistics` 从抽样结构求解最小二乘 `energy_shift()`，并把结果用于 fitting 末层 bias 初始化。新 LMDB 路径不再求解或使用这个能量偏置；仍保留抽样统计中用于平均原子数、最大原子数及批处理配置的部分。非 LMDB 路径继续使用原有 `energy_shift` 行为。

新建 LMDB 模型时，各元素 fitting 网络的**能量末层 bias 精确置零**，而非使用标准差为 1 eV 的正态随机值。隐藏层及末层权重保持原初始化。若使用双输出网络，只调整能量头的 bias，不改电荷头。网络前向仍输出残差原子能及其结构和；无需在 Adam、AdamW、KF 三套训练损失中各写一遍参考计算。

`train_ei` 与 `E_group` 不属于本功能；相关旧代码不作功能扩展，也不作为验收项。

## 4. Checkpoint、微调与旧模型

每个新 LMDB checkpoint 在原有 `state_dict`、优化器与训练进度之外，保存独立元数据，例如：

```text
energy_reference:
  version: 1
  representation: residual
  active_type: omat24
  atomic_numbers: [1, ..., 94]
  tables:
    mptrj:   [94 个 float64 值]
    omat24:  [94 个 float64 值]
    mae:     [94 个 float64 值]
```

`json_file.lmdb_type` 同时记录用户的标准化配置。运行时训练选择以当前 `nep.json` 的 `lmdb_type` 为准；三套系数由 checkpoint 提供并与代码内版本化表核对，避免导出时因代码更新而悄悄换表。若核对不一致，停止并明确提示。恢复同一数据类型的训练时继续使用原 checkpoint 参考口径、权重、动量和进度。

跨数据集微调必须明确指定新的 `lmdb_type`，加载残差网络权重，切换到新数据集参考表并重建新阶段的优化器和学习率计划。网络的残差函数作为初始化保留；切换参考表会有意改变物理总能的元素基线，这正是适配目标 DFT 数据的一部分，不应把旧表混进新标签。现有 `recover_train` 与从 `model_load_file` 开始新阶段训练的行为需要据此明确区分，并在日志中打印来源类型和目标类型。

没有 `energy_reference` 元数据的旧 checkpoint 视为**原始总能模型**。其默认 `totxt` 和推理沿用旧行为，不额外加参考值。旧 checkpoint 不得直接按新残差模型解释；如需作为新训练起点，应提供显式迁移：对每元素能量末层 bias 减去目标参考值，使迁移瞬间的物理总能预测保持不变，再按新口径继续训练。迁移时保留其他网络权重，优化器状态从新阶段重新初始化。禁止对旧模型静默加参考值。

## 5. 文本导出与用户可见推理

LMDB 训练自动生成 `nep5_<type>.txt` 与 `nep_model_<type>.ckpt`；周期性文件沿用 `epoch_<n>_` 前缀。若用户自定义 `model_name`，在扩展名前插入一次类型后缀，避免重复后缀。非 LMDB 文件名不变；若模型采用 `nep4` 格式，保留版本号并同样加类型后缀。

文本导出只对参数副本做一次转换：每个元素的**能量末层 bias** 从残差值变为 `bias + μ_Z`。`nep_to_gpumd.py` 目前将 PyTorch bias 取负后写入 GPUMD 文本，所以应先按 PyTorch 符号加参考，再走已有负号序列化；不能直接给文本数值加 `μ_Z`。电荷头、描述符参数、力及维里相关参数不变。转换后不回写 checkpoint 的 `state_dict`。

`MatPL totxt` 的接口：

```text
MatPL totxt nep_model_omat24.ckpt                 # 默认 checkpoint 的 active_type
MatPL totxt nep_model_omat24.ckpt -mptrj         # 选择该 checkpoint 保存的 mptrj 表
MatPL totxt nep_model_omat24.ckpt -omat          # 与 -omat24 等价
MatPL totxt nep_model_omat24.ckpt -mae
```

选项不区分大小写；未指定输出名时使用 `nep5_<选中类型>.txt`。现有第二位置参数指定输出文件名的形式继续支持；参数解析需消除“输出文件名”和“类型选项”的歧义。对无参考元数据的旧 checkpoint，带 `-mptrj/-omat/-mae` 的调用报错，防止重复平移能量。仅选择另一张参考表不会让未经微调的模型自动达到该数据集的精度。

checkpoint 推理及 `test` 的外部结果必须将参考和加回残差总能后再输出、保存与原始标签比较。训练和验证日志的能量残差 RMSE 与物理总能误差在同一结构上数值相同，因为预测与标签加的是相同常数；推理文件中的能量值则必须恢复到原始 DFT 口径。`nep*.txt` 推理已经含有折入 bias 的参考值，不能再次加回。

## 7. 验收与计算节点测试

小样本从以下位置读取，不扫描全量数据集：MPtrj 的 `MPtrj_virial_fixed.aselmdb`；Alexandria `train`；OMat24 的 AIMD 与 rattled 子目录。测试工作目录为 `/data/home/wuxingxing/datas/training_test/mgpus/omat24/unep_dev_test`。训练和较大样本测试仅提交到 `q4`、`3090`、`4090`、`q3`、`3080ti` 或 `new3080ti` 计算节点，不在登录节点执行。

验收项目：

1. 三种类型及 `omat` 别名的大小写解析正确；94 个原子序数映射正确，缺失类型和表不一致明确报错。
2. 对含不同元素和不同原子数的结构，逐一验证 `energy_res + Σ n_Z μ_Z = energy_raw`；训练/验证相同，力和维里标签不变。
3. 新建 LMDB 模型的能量末层 bias 为零；非 LMDB 初始化不变。
4. 单卡短训生成正确命名的 checkpoint 和文本；恢复同类型 checkpoint 后参考值及能量连续；跨类型微调使用新类型标签和参考值。
5. 同一结构的 checkpoint 物理总能与文本力场总能一致；两条推理路径的力、维里一致；测试报告与原始 DFT 总能比较。
6. 旧 checkpoint 默认行为不变；显式迁移前后物理预测连续；旧 checkpoint 搭配类型选项不会静默重复加参考。
7. 短时多进程测试确认所有 rank 使用相同参考表、采样和 checkpoint 元数据，且无额外全量 LMDB 预扫描。

验收后只保留本地 `nep-dcu/unep` 分支修改，用户自行决定提交和推送 GitHub。
